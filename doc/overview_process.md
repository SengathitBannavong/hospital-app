# User Feature Progress Overview

This overview is from the mobile app user's point of view. It measures what a
patient/user can actually use in the Flutter app, not raw backend endpoint
coverage.

## Summary

Overall user-facing progress is about `83%`.

The strongest completed areas are authentication, medical tasks (now with a
per-task detail page), prescriptions, **notifications (pagination + settings +
60s polling fallback + optional push + tests)**, profile basics with
device-token registration, indoor
map, QR positioning, the **dynamic Info/Utility hub** (FAQ/About/Contact +
weather + app-update check + feedback), **SOS quick-send**, asset/wheelchair and
staff-request flows (now surfaced on the Home grid and via a shared location
picker), simulated navigation **with offline turn-by-turn voice guidance**, and
the first complete **Chat** surface.

**Localization (branch `add-eng-to-vn`):** the app now ships full
English/Vietnamese strings through Flutter's official `gen-l10n` (ARB) pipeline
with a language toggle in Settings that persists across restarts
(`LocaleController`, secure storage, system-locale fallback). The map module —
the last feature holding hardcoded strings — was migrated end-to-end (~110
keys), and the longer Vietnamese labels surfaced two latent layout bugs that are
now fixed (extended FABs forced into `CircleBorder` clipped their label →
`StadiumBorder`; the analytics toggle row overflowed → `Expanded`). Turn-by-turn
maneuver/voice text (Vietnamese-only audio assets) and data-layer fallbacks are
intentionally deferred.

The biggest remaining gaps are feedback image attachments, deeper chat room
creation/management, deeper live navigation sync, and — critically on the
backend — a real **push sender + notification triggers** (without which
notifications stay seed-only). A second backend cluster blocks **Asset /
Wheelchair**: `release_asset` keys off `station_name` not the PK, every device
error returns `message:"OK"`, and `asset_stations` carries no location (so
release-by-position is impossible). `my_booking` has since shipped and is wired
(2026-06-17), so booking recovery is now authoritative rather than heuristic.
See `context/backend-tasks.md`,
`context/overview_system.md`, and `doc/asset_wheelchair_backend_gap.md`.
